二、下位机 HOST LINK 握手协议 V4 ★

V4 保留 V3 的 HOST WAIT/主机身份门禁，并为 RPI 二进制会话增加 wire version + capability bitmap 协商。单根 USB 线，COM/RPI 可随时重新声明，每次声明即停车清状态，绝不恢复上一主机的目标。

十二、下位机 二进制位姿协议与会话 ★（HOST V4 / wire v2）

动机：ASCII POSE SET 的完成匹配依赖坐标文本（响应迟到/丢失时有歧义）且无完整性校验。 二进制协议给每个事务一个非零 goal_id，全部终态事件回带该 id——从协议层面消除歧义；帧含 SOF+长度+CRC。 数值常量权威源：protocol/rpi_binary_protocol.json；生成器同步 C/Python/Markdown，--check 防漂移。 行为规范：docs/binary-pose-protocol.md。ASCII 完整保留给 COM/TUNE/自检；二进制仅在显式握手后接管 USART1。

条件动作

二十六、map_frame.py —— 固定地图启动锚定 ★

把"固定场地图纸上的车体中心航点"转换为 POSE SET 需要的 OPS 原始航点。原理：以"标称起点 → 本轮自检读到的实际 OPS 起点" 做一次刚体变换（旋转 yaw_delta + 平移），场地放置误差成为本轮整体偏差，由视觉精对准兜底——无需现场逐点标定。

成员 / 函数作用备注
MapGoal(name,x,y,yaw,timeout,profile)地图纸中的车体中心航点（含速度档）—
StartAnchoredMapFrame(nominal_start_center, actual_start_ops, ops_offset)锚定帧：构造时全字段 isfinite 校验ops_offset 默认 (0,25) 传感器偏置
to_ops_goal(map_goal)① actual_center = actual_ops − rotate(offset, actual_yaw)（起点中心） ② delta = map_goal − nominal；rotate(delta, actual_yaw−nominal_yaw) ③ target_yaw = wrap(actual_yaw + goal_yaw − nominal_yaw) ④ target_ops = target_center + rotate(offset, target_yaw)（终点传感器偏置按目标航向补偿）安全 非有限输入抛 ValueError；4 个单测覆盖恒等/旋转/终点偏置/零位移
限制（docstring 已声明）：放置误差会成为本轮地图的整体误差——粗导航后必须由视觉/机构精对准兜底， 不适用于对绝对精度要求高于放置精度的场景。

27.2 go 门禁（六重前置，全部满足才发车）

#条件失败输出
1--armed 且 runtime READY 且地图锚定帧已建立[GO REJECTED] requires --armed and READY
2vision.health().healthy（视觉线程活着、帧龄≤1s、无错误）[GO REJECTED] vision is not healthy
3路线空闲（route != RUNNING）[GO REJECTED] route already running
4-5观察门禁：目标类型+编号+来源+置信度(默认0.8)+新鲜度(0.5s) 全过[GO REJECTED] no fresh matching observation
6READY 但无 OPS 起点位姿 → 直接急停+FAULT（set_control_ready 内）[FAULT] READY without an OPS start pose

说明：视觉只做"相机活着且看到预期目标"的健康前置，运动目标永远来自配置的预标定地图航点 （frame.to_ops_goal 换算），不经像素生成——物料 aligned/safe_to_pick 属抓取域概念，不进本运动门禁。 默认配置 map_goal == 标称起点（零位移），首次 SSH 联调天然安全。 发车链路：SpeedProfileController 切档 → RouteRunner(单航点) → Navigator → SerialBridge → STM32； 离开 READY 时 profiles.mark_unknown() 保证重自检后重新切档。配置校验（vision_motion_debug.json）： material 编号与 target_id 一致性、超时/置信度范围、offset 有限性，错误退出码 2。

附录：各状态机的共同安全不变量

① 任何异常 → 锁存急停，绝不自动恢复旧目标（重连/重新声明主机后必须重新自检）。
② 超时一律按"固件可能已在运动"处理：回复丢失 ≠ 未发车，START/取消确认超时都 emergency_stop()。
③ 单航点串行：串口上任意时刻最多一个未完结 POSE SET（Navigator→RouteRunner→Mission 逐层保证）。
④ 双重停车保险：下位机 ChassisSafety 每循环独立监督，上位机桥+导航器超时锁存——任一侧失效另一侧仍能停车。
⑤ 限速与目标原子提交：RPI 二进制运行把速度档暂存到 Pi，并与下一目标合为 opcode 84；固件整包校验后同时接受，拒绝时不改限速、不发车。ASCII 人工调试仍保持 PID LIMIT 先于 POSE SET。
⑥ 职责红线：树莓派只提交目标位姿，绝不持续发四轮速度、绝不直接驱动电机；STM32 独占闭环与电机控制。
⑦ 视觉只读感知：视觉包无串口/协议/导航依赖（架构测试固化）；观察只映射预标定航点或被门禁拒绝；像素≠毫米； 未标定功能默认拒绝；控制边界事件统一清空视觉缓存。
⑧ 主机所有权唯一：HOST WAIT 门禁未握手前只放行探测/停车命令；COM/RPI 重新声明即停车清状态； RPI 链路运动受 1.5s HOST LOST 保护，COM 依赖操作员看护 + 固件超时/故障兜底。
⑨ goal_id + pending 双重事务身份：事件按当前 goal_id 过滤；响应还必须匹配存活 sequence/opcode；QUERY 额外校验 request_goal_id 与 query_context，旧目标迟到状态不能影响新目标。
⑩ 会话与发送故障收口：每次串口打开先 SESSION_PROBE，遗留会话先 STOP 再等待超时；断线清全部 pending；STOP/fault 走 urgent，控制走有界 FIFO，遥测只保留最新；USART1 错误下一主循环立即停车拆会话；二进制 active 时 printf 被抑制。
